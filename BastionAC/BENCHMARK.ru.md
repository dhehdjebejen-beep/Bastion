# Замер нагрузки BastionAC (21.10.2026)

<p><a href="BENCHMARK.md">English</a> · <b>Русский</b></p>

Сколько процессора стоит античит на сервере с двумя ядрами — как у сервера,
для которого Bastion писался. Для сравнения тот же замер сделан с Grim.

## Условия

- **Сервер:** Fabric 1.21.11 + Fabric API, плоский мир, мирный режим,
  дальность прорисовки и симуляции 4 чанка, сжатие сети выключено.
  Процесс сервера привязан к **двум ядрам** (Ryzen 7 8845H), память 2 ГБ.
- **Конфигурации:** чистый сервер; + BastionAC 3.5.0-beta+build.4 (без
  BastionAuth и BastionClaims); + Grim 2.3.74-39d7eb1 (сборка под Fabric с
  Modrinth). У обоих античитов настройки по умолчанию.
- **Игроки — боты** (протокол 1.21.11, на двух других ядрах). Они ведут себя
  как ванильный клиент: 70 % ходят по кругу с ванильной физикой бит в бит
  (округления float, таблица синусов Minecraft, трение травы, первый тик после
  телепорта в воздухе), поворачивают камеру целыми шагами сетки
  чувствительности; 30 % бьют свою неуязвимую свинью раз в 11–16 тиков.
  Отвечают на keep-alive и ping-транзакции, подтверждают телепорты и чанки.
  Боты стоят сеткой через 96 блоков, вне видимости друг друга.
- **Проверка честности ботов:** за все замеры у BastionAC 0 нарушений, у Grim
  0 алертов (с включённым verbose — 0 расхождений движка предсказаний), ни одного
  кика, ни одного отката в окне замера.
- **Замер:** минута прогрева, затем 120 секунд — процессорное время процесса
  сервера (% одного ядра) и среднее время тика (`/tick query`).

## Результаты

50 игроков, три повтора каждой конфигурации в разном порядке:

| | CPU, % одного ядра | к чистому серверу | время тика |
|---|---:|---:|---:|
| чистый сервер | 88,6 ± 5,1 | — | 33,2 мс |
| + BastionAC | 89,3 ± 1,9 | +0,6 | 33,7 мс |
| + Grim | 100,3 ± 3,1 | +11,6 | 36,2 мс |

Отдельные прогоны:

| игроков | чистый сервер | + BastionAC | + Grim |
|---:|---:|---:|---:|
| 50 | 88,4 % · 33,8 мс | 90,2 % · 34,1 мс | 102,9 % · 36,8 мс |
| 100 | 120,5 % · 76,3 мс | 122,0 % · 74,0 мс | 134,3 % · 82,0 мс |

Добавка BastionAC в пределах разброса измерений (до ~2 % одного ядра на
50–100 игроков). На 100 игроках сервер уже перегружен сам по себе (тик дольше
50 мс): почти всё время уходит на мир — у каждого бота свой участок чанков.
200 игроков на двух ядрах не выдерживает и сервер без античита: тик дольше
60 секунд, сторожевой таймер останавливает сервер.

Ping-транзакции к клиентам за прогон 50 игроков: BastionAC ~4,7 тыс.
(отброс и замер задержки), Grim ~106 тыс. (транзакция на каждый тик игрока).

## Ограничения

- Боты — модель игры: честные, без читов. Аргус в замере почти не работал (нет
  алертов — нет дел); стоимость разбора дела измерена отдельно: ~150 мс на
  10 минут игры в фоновом потоке, не больше четверти одного ядра.
- Grim на Fabric — альфа-сборка; его база истории (SQLite) не поднялась
  (нет драйвера), остальное работало.
- Один тип нагрузки (ходьба по кругу и удары по мобу), плоский мир.

## Как повторить

Скрипты в [`tools/acbench`](tools/acbench): `bench_bots.py` — боты,
`bench_run.py` — прогон конфигураций, `bench_repeat.py` — повторы с ротацией
порядка. Сырые результаты — `tools/acbench/results/`.

Нужны Windows (привязка к ядрам и время процесса берутся из kernel32), Python 3
и JDK 21. В папку `$ACBENCH_ROOT/server` положите `libraries/` и `versions/`
серверного Fabric 1.21.11, пути к jar задайте переменными `ACBENCH_JAVA`,
`ACBENCH_FABRIC_API`, `ACBENCH_BASTIONAC`, `ACBENCH_GRIM`:

```bash
python bench_repeat.py 50 3 60 120          # 50 игроков, 3 повтора, прогрев 60 с, замер 120 с
python bench_run.py vanilla,bastion,grim 100 60 120
```
